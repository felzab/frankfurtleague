## 1. Contract

### 1.1 Endpoint inventory

All paths are prefixed `/api/v{API_VERSION}`. Guards are declared at router level and inherited by
every endpoint in the router.

`GET /spiele/action_required` below — because each side of a fixture carries a `disqualifikation`
joined from `saison_teams` rather than embedded (I32). One shape across all of them, since one Zod
schema mirrors them.

match ([ADR-0040](../_decisions/0040-a-form-that-outgrows-a-dialog-becomes-a-page.md)).

### 1.3 The match write path

`PATCH /spiele/{spiel_id}`, step by step.

| Step | Behaviour                                                                                                                                                                                                                                   | What breaks if changed                                                                                                                                   |
| ---- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 0    | The stored fixture is read in full, and `apply_payload_to_spiel` normalises the payload against it — steps 1 and 1a are that function's, stated nowhere else ([ADR-0041](../_decisions/0041-a-voided-result-is-named-before-it-is-lost.md)) | The `dry_run` preview and the save would each hold their own opinion of what a payload means, and the preview would name the wrong fixtures (I29)        |
| 1    | `ergebnis` derived as `f"{team1.tore}:{team2.tore}"`, `None` if either is `None`                                                                                                                                                            | A client could submit a result disagreeing with the goals rendered beside it                                                                             |
| 1a   | `elfmeterschiessen` kept only on a fixture outside the Gruppenphase whose two goal counts are equal, discarded otherwise — a level group draw discards it too                                                                               | A shoot-out would stand against a fixture one side won on goals, or against a group draw that has no tie to break (I25)                                  |
| 1b   | Wiring the season cannot hold is a 409 (`REQ-WIRING-001`), decided by `find_wiring_refusal` inside the transaction, before the write ([ADR-0038](../_decisions/0038-the-write-path-refuses-wiring-the-season-cannot-hold.md))               | A duplicate feed, a dangling source or a hand-set team on a maintained side would be written, and the last of them silently reverted in the same request |
| 1c   | An OCCUPANT the season cannot hold is a 409 with its own code, decided by `find_eligibility_refusal` and `judge_spieltag_occupancy` beside it ([ADR-0042](../_decisions/0042-a-team-is-fielded-once-per-spieltag.md))                       | A disqualified team, or a team playing twice on one matchday, would be written and nothing would say so (I30)                                            |
| 1d   | A side carrying goals on a played fixture may be switched but not emptied — 409 `REQ-RESULT-001`, decided by `find_result_removal_refusal`                                                                                                  | A result would survive as a half-fixture: goals standing against a slot with nobody in it                                                                |
| 1e   | The fixture's `datum` must fall inside the span of the Spieltag it belongs to — 409 `REQ-DATE-001`, decided by `find_fixture_date_refusal` against the matchday read in-session. A fixture whose matchday is missing is left alone          | A matchday would silently hold a fixture outside its own dates, and `spieltag_id` is on no payload, so nothing else could put it back                    |
| 1f   | A venue or a referee already serving another fixture of the same day less than four hours away is a 409 `REQ-CLASH-001`, decided by `find_clash_refusal` across **every** season                                                            | One ground or one referee would be booked twice at once — and a double booking crosses competitions, which a season-scoped read would miss               |
| 1g   | Steps 1b to 1f all run in `judge`, which the save and the `dry_run` preview both call                                                                                                                                                       | A preview could promise a write the save then refuses                                                                                                    |
| 2    | Payload written wholesale with `$set`, at the helper's default `ReturnDocument.BEFORE`. The keys come from `FLPatchSpielDataPayload`'s field set plus `ergebnis`                                                                            | A field absent from the payload is **overwritten**, not preserved; keys taken from the normalised fixture instead would put `saison_id` in the `$set`    |
| 3    | A `None` return means no document matched — the 404 branch                                                                                                                                                                                  | A missing match would be reported as a successful edit                                                                                                   |
| 3a   | Every side a Spieltag clash releases is emptied, **before** step 5, and named in `released_sides` (I30)                                                                                                                                     | A slot the release opens would stay empty until the next save, and the preview would name a different set of fixtures than the save moved                |
| 4    | Where a slot's `Quelle` names a group placing, the standing is derived through `build_team_pipeline`, inside the session — and only for the groups referenced; a season whose bracket references none skips the read                        | A group the edit just completed would still read as unfinished, and seed nothing                                                                         |
| 5    | The season's bracket is resolved and every disagreeing fixture written (I23, I24a, I25), each reported with the result that write destroyed (I29)                                                                                           | A winner would never reach the fixture whose `Quelle` names its match, and a deleted scoreline would read as an ordinary pairing change                  |

**`dry_run=true` runs step 0, every refusal in `judge`, and a read-only step 5, and writes nothing**
(I29). It resolves
the bracket over a season assembled in memory — the patched fixture and any released sides substituted
in — and returns the same `FLPatchSpielDataResponse` the save does. No transaction: nothing is written,
and a preview that took a write lock would be paying for a question.

**The season comes off step 0's full read**
(`fl_backend/app/api/spiele/admin_router.py :: patch_spiel_data`, `saison_id = stored.saison_id`), and
step 2's return is read for one thing only: `None` means nothing matched, which is the 404 branch.
Nothing here consults the pre-image's content, so this path takes the helper's default (I2) rather than
needing it. Step 5 must be scoped to one season, because `spiel_nr` identifies a match _within_ a
season, and `saison_id` is on no payload — so the `$set` cannot have moved the fixture out from under
the scope.

**More than one document, and still one transaction**, because the result and the advancement it causes
are one fact. Both reads in steps 4 and 5 take the session, or they would see the snapshot from before
step 2 and resolve the bracket from the match as it was.

**A shoot-out rides with the result and is read only by the bracket** — step 5 takes a winner from it,
and the derived table does not (I25, I25a).

**No team document is written.** The league table is computed from the match documents by `GET /teams`
(I1), so entering a result moves the table on the next read. The frontend still invalidates the `teams`
cache tags in the same action — the data it caches changed even though no team document did.

### 1.4 Error codes and failure responses

**Every failure response body is `{error_code, correlation_id}`** — the full code table, the field
contract and the correlation-id design are in [`docs/logging/spec.md`](../logging/spec.md), which every
failure line and response must follow ([ADR-0032](../_decisions/0032-one-correlation-id-per-request-one-document-per-line.md)).
The invariant the tests pin here: the code on the wire and in the log is the **exception's own**
(`fl_backend/app/core/exceptions.py :: BaseAPIException`), checked by
`fl_backend/tests/api/test_error_responses.py`.

**A `DuplicateKeyError` maps to a 409 through a dedicated handler**
([ADR-0027](../_decisions/0027-the-write-path-is-resource-first-in-a-second-router.md)): a natural-key
collision on a create is an ordinary outcome rather than a server fault. Starlette resolves handlers by
walking `type(exc).__mro__`, so registration order does not matter — the most specific registered class
wins.

**The match write path raises its own 409** (`REQ-WIRING-001`) for bracket wiring the season cannot
hold — §1.3 step 1b, [ADR-0038](../_decisions/0038-the-write-path-refuses-wiring-the-season-cannot-hold.md).
Same status, different meaning: no index refused anything, the season's current state did, and the
form prevents these shapes — so a request carrying one is stale or racing another admin.

**The rest of this path's rules carry codes of their own rather than `REQ-WIRING-001`'s**
([ADR-0042](../_decisions/0042-a-team-is-fielded-once-per-spieltag.md)): that code's advice is "reload
the page", which is right for a season that has moved and wrong for every one of these, where the
season has not moved at all.

| Code                  | Refuses                                                                              |
| --------------------- | ------------------------------------------------------------------------------------ |
| `REQ-ELIGIBILITY-001` | A disqualified team, newly fielded                                                   |
| `REQ-ELIGIBILITY-002` | A newly fielded team with no `saison_teams` row for the fixture's season             |
| `REQ-SPIELTAG-001`    | A team that would play two fixtures of one Spieltag, where the clash cannot be moved |
| `REQ-RESULT-001`      | A side carrying goals on a played fixture, emptied rather than switched              |
| `REQ-DATE-001`        | A date outside the span of the matchday the fixture belongs to                       |
| `REQ-CLASH-001`       | A venue or referee already serving another fixture less than four hours away         |

**One code per rule, never one per side.** The failure body is `{error_code, correlation_id}` and
nothing else (L4), so the code is the only channel — and "team1 is disqualified" and "team2 is
disqualified" are one failure mode, which is what the code table's own rule keys on. The form works out
which side from the payload it submitted, using the predicates its pickers already evaluate.

**A malformed id: 404 in a path, 422 in a query — a deliberate split**
([ADR-0057](../_decisions/0057-a-path-identifies-a-query-validates.md)). The `objectid` convertor
(`fl_backend/app/core/routing.py :: by_id`) means `/spiele/not-an-id` matches no route at all, and a
season id — a four-character string, never an ObjectId — reaches the lookup and 404s there instead. A
query parameter carries input, so malformed input fails validation like any other: `REQ-VAL-001`, 422.
`REQ-OID-001` (400) is the net behind both — bson's `InvalidId` mapped wherever a handler builds an
ObjectId no convertor or model has checked — and through routed traffic it is expected to be
unreachable.

### 1.6 The test suite

**The backend is the source of truth and the frontend mirrors it**, so the validation rules live here
and this suite pins them. Without it a constraint could be relaxed — to make a stubborn 422 go away,
say — and nothing would notice, because a loosened rule fails no test and breaks no build.
`fl_backend/tests/README.md` navigates the tree; the contract is here.

**Covers:** Pydantic model validation chiefly — every constrained model accepts a valid payload, rejects
the specific bad value each constraint exists to stop, and still accepts the legitimate edge cases that
look like bad values (an empty `stadtteil`, a null `ergebnis` for an unplayed match, an integral float
`mietpreis`). Plus the declared domain model
([ADR-0053](../_decisions/0053-the-domain-model-is-declared-and-conformance-checked.md)), the database's
own `$jsonSchema` validators and unique indexes
([ADR-0020](../_decisions/0020-the-database-enforces-its-own-invariants.md)), the filter builders, the
response envelope, every router's admin guard (`fl_backend/tests/api/test_admin_guard.py`), the refusal
paths, and both aggregation pipelines — what a pipeline _says_ and what MongoDB _computes_ from what it
says. What is reached only indirectly is §4.

#### The two tiers, and the marker that separates them

| Tier        | Selected by         | Needs Docker | Cost                                                  |
| ----------- | ------------------- | ------------ | ----------------------------------------------------- |
| **Default** | everything unmarked | no           | under a second                                        |
| **`db`**    | `@pytest.mark.db`   | yes          | 14.3s warm (2026-08-05); cold adds the `mongo:8` pull |

`fl_backend/pyproject.toml :: addopts` deselects the marker, so a bare `pytest` runs the fast tier only.
A command-line `-m` overrides it — addopts are prepended rather than merged — so `pytest -m db` runs
exactly what the default run skips. Why each of the other flags is there is commented at that same key.

**A test that touches the database carries `@pytest.mark.db`.** Without it the test runs in the fast
tier, where there is no container, and fails for a reason that looks unrelated to what it is testing.
`--strict-markers` catches a misspelled marker; nothing catches an omitted one.

**The marker exists to keep the fast tier fast**, and the case for a real `mongod` behind it —
`mongomock` cannot execute this pipeline, and a check against the live database tests the data rather
than the code — is [ADR-0023](../_decisions/0023-a-real-mongod-behind-a-deselected-marker.md)'s. The
gate's `--backend` scope runs the default tier only; the `db` tier is its own scope and its own parallel
CI job ([`docs/ops/spec.md`](../ops/spec.md)).

An `*_execution.py` module runs against a real `mongod` what its structural sibling asserts about the
dict, and neither replaces the other: the structural test fails when a rule is **deleted**, the
executing one when a rule is present but **wrong**. `fl_backend/tests/api/test_spiele_pipeline_execution.py`
has no structural sibling — the spiele pipeline is exercised against the engine alone.

#### What the suite reads, and what it does not

Every field the application under test needs is passed explicitly to
`fl_backend/tests/config.py :: build_test_config`, and init arguments outrank every other source in
pydantic-settings, so a checkout with no `.env` runs the whole suite — which is what CI is — and a
failure means the code rather than the machine. **A field that is not passed still falls back to
`.env`**, which the settings model declares (`fl_backend/app/core/config.py :: model_config`), which is
why a test about a default asserts on the model's field rather than on a constructed instance.

**The container fixture lives in the root `conftest.py`**, not in `api/`, because two suites want a
database. It is session-scoped, so one `mongod` serves both, and it yields the _container_ rather than
a client: the pipeline suite reads with pymongo and the constraint suite drives Motor, which needs the
connection URL.

**One test guards a rule nothing else can.**
`fl_backend/tests/core/test_constraints.py :: test_every_mirrored_model_matches_its_validator` compares
each Pydantic model's stored field names against the `$jsonSchema` its collection carries and fails
naming the field, which is what makes a hand-written third copy of the schema affordable (I17).

There are **no `__init__.py` files** — `pyproject.toml` sets `--import-mode=importlib`, which needs none
and cannot suffer same-basename collisions.

#### Conventions

- **Fixtures are factories, not constants.** Every fixture returns a callable producing a fresh valid
  payload; a test calls it with the one field it wants to break, so each case states exactly what makes
  it invalid and no two cases can leak state through a shared mutable dict
  (`fl_backend/tests/conftest.py :: _factory`). Payloads are keyed the way MongoDB serves them — `_id`,
  not `id` — because that is the validation alias the models declare.
- **Reject-cases are parametrised.** One `pytest.mark.parametrize` per rule, listing every value that
  must fail, so adding a case is one line.
- **Comments explain the _why_, not the assertion.** Where a constraint exists because of a specific
  defect, the test says so.
- **Assert _which_ field failed when more than one could**, using the `assert_rejects` fixture
  (`fl_backend/tests/conftest.py :: assert_rejects`): a bare `pytest.raises(ValidationError)` passes
  whatever went wrong, so a test meant to prove one constraint stays green while an unrelated typo in
  the payload satisfies it and the constraint it names goes unenforced. Use it wherever the payload is
  hand-built rather than produced by a factory.
- **The `db` corpus is documented once**, in `fl_backend/tests/api/conftest.py`: its header derives
  every expected figure by hand, the tests assert against them, and each seeded team exists to make
  exactly one invariant observable.

## 3. Violation → remedy

| Symptom                                                  | Cause                                                                                        | Remedy                                                                                            |
| -------------------------------------------------------- | -------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------- |
| League table does not change after a result edit         | A stale frontend cache, not the backend                                                      | The table is recomputed per request (I1); check that the Spiel action still invalidates `teams`   |
| A cancelled match still counts in the table              | Working as intended — it is a forfeit (I1a)                                                  | Nothing. Clear the `ergebnis` if it should not count                                              |
| A semi-final lost its result after a QF edit             | Working as intended — its occupant changed (I23)                                             | Nothing. The goals were scored by a team no longer in the fixture; re-enter the new one           |
| A winner did not reach the next fixture                  | Its `Quelle` is `null`, or names a `spiel_nr` the season does not have                       | Set the source on that side in the admin form; the toast names every fixture the save moved (I23) |
| A knockout slot stays empty and nothing moves it         | One of the derived bracket faults (I28) — the action-required list names which, and why      | Correct the source it names, or clear the `Quelle` and enter a side by hand                       |
| A group-seeded slot is still empty                       | That placing is not final yet — some result in the group could still change it (I24a)        | Nothing. It fills itself on the first save after the group can no longer go another way           |
| A group-seeded slot was reported, not filled             | The `platz` exceeds what the group can produce, or the chain cannot separate it (I24c)       | Fix the `platz`, or take the slot over by choosing "Manuell" and entering a side                  |
| A fault's toast was missed                               | Nothing stores it, by design (I28)                                                           | Open the action-required list, which re-derives every fault on every request                      |
| A seeded slot changed after a forfeit was awarded        | Working as intended — a cancelled, result-less fixture is not outstanding (I24a)             | Nothing. The forfeit's save re-resolved the bracket against the standing it changed               |
| A team cannot be entered on a bracket side               | The side has a `Quelle`, and the write path refuses a hand-set team beside one (I27)         | Choose "Manuell" on that side, and the slot is yours                                              |
| A save comes back 409 with `REQ-WIRING-001`              | The form was built against a season that has moved — a second tab or another admin           | Reload the page and repeat the edit against the current bracket (I27)                             |
| A save comes back 409 with `REQ-ELIGIBILITY-001`         | The team is disqualified from this season, and the payload newly fields it (I30)             | Pick another team. Reloading changes nothing — the season has not moved                           |
| A save comes back 409 with `REQ-ELIGIBILITY-002`         | The team holds no `saison_teams` row for this season, so it is not in the competition        | Add the junction row, or pick a team that is in the season (I11)                                  |
| A save comes back 409 with `REQ-SPIELTAG-001`            | The team already plays this Spieltag on a side the resolution maintains (I30)                | Clear that fixture's `Quelle` on the occupied side, or pick another team                          |
| A fixture was emptied by a save that never named it      | Working as intended — a team was fielded elsewhere on its Spieltag (I30)                     | Nothing. The response's `released_sides` names every one, and the toast offers 15s to undo (I29)  |
| A warning named fixtures that lost nothing               | It cannot: the warning is a dry run of the write path, not a guess (I29)                     | Check that the preview actually answered — no answer renders no banner, which is not "no risk"    |
| A level knockout advanced nobody                         | No shoot-out is recorded against it, so it has no winner (I25)                               | Enter the shoot-out on that match; the slot fills on that save                                    |
| A shoot-out did not change the league table              | Working as intended — it is a draw for every derived figure (I25a)                           | Nothing. Only the bracket takes a winner from a shoot-out                                         |
| A shoot-out vanished after an unrelated edit             | Its fixture's occupant changed, so the whole result went with it (I25b)                      | Re-enter the result and the shoot-out for the side that is in the fixture now                     |
| A team's page and the Saisontabelle disagree             | Working as intended — two scopes (I1c)                                                       | Nothing. The page counts every phase, the table counts the Gruppenphase                           |
| Every team's table reads zero                            | A season resolved to one with no matches                                                     | Check `saison_id`; an unknown season 404s rather than returning an empty list                     |
| Venue rent becomes 0 after an unrelated edit             | A Pydantic default was added to `mietpreis`                                                  | Remove it (I6)                                                                                    |
| A team vanishes from `/teams`                            | No `saison_teams` row for that season                                                        | Create the junction row (I11)                                                                     |
| `/dashboard/saisontabelle` fails to load                 | A group key missing from the grouped response                                                | I10 — should be impossible now                                                                    |
| A create comes back 409                                  | A unique index still holds the key                                                           | The retired row keeps its slot on purpose (I20). Reactivate it, or choose another key             |
| A retire comes back 409 with `REQ-RETIRE-001`            | The club is entered in a running or planned season                                           | Wait for the season to end, or leave the club active — a season is left only by disqualification  |
| An entry comes back 409 with `REQ-ENTER-001`             | The season is running or past — a team enters a season only while it is `future`             | Enter the team into the next planned season instead                                               |
| An entry or move comes back 409 with `REQ-ENTER-002/003` | The group is outside `rules.number_of_groups`, or already holds `rules.teams_per_group` rows | Pick a group the season runs that still has space; a disqualified team's place stays taken        |
| A retired venue is missing from an admin picker          | The default read filters it out                                                              | Pass `include_inactive=true` — a switch, not a value to match on                                  |
| A disqualified team still appears in the table           | Working as intended — it keeps its row and only loses its placing (I24b)                     | Nothing. The placings walk past it and the team below takes the place                             |
| A PATCH to a junction row comes back 422                 | `disqualifikation` is required on the payload and the form omitted it (I31)                  | Send the record, or `null` to lift one. There is no partial update of a junction row              |
| 401 with `REQ-AUTH-002`                                  | Wrong or missing `base` key                                                                  | Check `INTERNAL_API_KEY_BASE` matches on both sides                                               |
| 503 with `Retry-After: 30`                               | Database unavailable                                                                         | `DB-CONN-001` — check MongoDB                                                                     |
