## 1. Contract

### 1.1 Endpoint inventory

All paths are prefixed `/api/v{API_VERSION}`. Guards are declared at router level and inherited by
every endpoint in the router.

**Every route that serves matches runs one aggregation**, the admin reads below included,
because each side of a fixture carries an `austritt`
joined from `saison_teams` rather than embedded (I32). One shape across all of them, since one Zod
schema mirrors them.

**Every resource carries a `GET /{id}` whether or not something calls it** — the callerless ones
are §4's. `/teams/{team_id}` serves the team detail pages and the admin team editor, which reads
it once per season because a 404 is the read that answers "not in this season" (I11);
`/spieltage/{spieltag_id}` serves the matchday editor. Each editor is addressed by its own id alone and
reads the season off the document, the match editor included — though that one reads
`/spiele/{spiel_id}/admin` rather than the public single read.

is addressed resource-first, with the id in the path. `tests/api/test_admin_guard.py` walks
`app.openapi()["paths"]` and fails if any of them loses its guard.

**There is no `DELETE /saisons/{id}`**, and none on `/teams/{team_id}/saisons/{saison_id}` or on
`/spieltage/{spieltag_id}` either — `spieltage` carries no `inactive_since`, so a matchday has no
field to stamp and none to clear. The absent verbs on `/spiele` are I26's, and the rows above cite it.

**Every `spieltage` response carrying a matchday injects `anzahl_spiele` before validation, writes
as much as reads.** The field is required on `FLSpieltag` and sits on no document, so
both reads and `PATCH /spieltage/{spieltag_id}`, the one write that echoes a matchday, pass the
document through `fl_backend/app/api/spieltage/services.py :: with_expected_matches` first.
`POST /spieltage` needs none: it answers with an id alone and validates no stored document.
**The rule reaches every echo, not only the reads** — a new write endpoint
that echoes a matchday injects too, or it answers 500 from its own response.

**`/saisons/{saison_id}/gruppen/swap` writes `saison_teams` from the season's router, which is the one
place the resource-first rule bends and does so deliberately.** A swap is one decision
about a season; the junction endpoint above addresses one club, which cannot express it atomically.

### 1.3 The match write path

`PATCH /spiele/{spiel_id}`, step by step.

| Step | Behaviour                                                                                                                                                                                                                                                                                                                                                     | What breaks if changed                                                                                                                                                                                           |
| ---- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 0    | The fixture's `saison_id` is read on its own, and that read is what answers 404 for an id no fixture holds; the season's `rules` follow it, outside any transaction                                                                                                                                                                                           | A payload naming no fixture would reach the judgement, and a forfeit awarded from a constant could disagree with the season being played (I3a)                                                                   |
| 1    | `judge` reads the season one fixture over the list cap, runs every refusal below it, and normalises the payload last; the save and the `dry_run` preview both call it                                                                                                                                                                                         | A preview could promise a write the save then refuses, and a truncated season would be judged with a hole in it rather than detected (I45)                                                                       |
| 1a   | The payload's `sonderereignis` is judged FIRST, against the goals beside it and nothing else — goals on a state that awards none is 409 `REQ-STATE-002`, a no-show on an unresolved side 409 `REQ-STATE-003`, both decided by `find_state_refusal`                                                                                                            | The event the admin chose is what the rest of the judgement is about, so a contradiction inside it would surface as a bracket fault or a silently discarded score                                                |
| 1b   | Wiring the season cannot hold is a 409 (`REQ-WIRING-001`), decided by `find_wiring_refusal` inside the transaction, before the write                                                                                                                                                                                                                          | A duplicate feed, a dangling source or a hand-set team on a maintained side would be written, and the last of them silently reverted in the same request                                                         |
| 1c   | An occupant the season cannot field is a 409 with its own code, decided by `find_eligibility_refusal` against the `saison_teams` rows read in-session                                                                                                                                                                                                         | A team that left the season, or one the season never entered, would be written onto a fixture and nothing would say so (I30)                                                                                     |
| 1d   | A side carrying goals on a played fixture may be switched but not emptied — 409 `REQ-RESULT-001`, decided by `find_result_removal_refusal`                                                                                                                                                                                                                    | A result would survive as a half-fixture: goals standing against a slot with nobody in it                                                                                                                        |
| 1e   | A team fielded twice on one Spieltag is 409 `REQ-SPIELTAG-001` where the clash cannot be moved, decided by `judge_spieltag_occupancy` — which otherwise names the sides step 3a empties                                                                                                                                                                       | A team would play two fixtures of one matchday and nothing would say so (I30)                                                                                                                                    |
| 1f   | The fixture's `datum` must fall inside the span of the Spieltag it belongs to — 409 `REQ-DATE-001`, decided by `find_fixture_date_refusal` against the matchday read in-session. A fixture whose matchday is missing is left alone                                                                                                                            | A matchday would silently hold a fixture outside its own dates, and `spieltag_id` is on no payload, so nothing else could put it back                                                                            |
| 1g   | A NEWLY assigned venue or referee the league does not hold, or holds as retired, is a 409 `REQ-BOOKING-001`, decided by `find_booking_refusal` against the rows read for it; a reference already stored is left alone                                                                                                                                         | A fixture would name a ground or an official nothing in the league answers to, and step 1k would have no row to compose its name from                                                                            |
| 1h   | A venue or a referee already serving another fixture of the same day less than four hours away is a 409 `REQ-CLASH-001`, decided by `find_clash_refusal` across **every** season                                                                                                                                                                              | One ground or one referee would be booked twice at once — and a double booking crosses competitions, which a season-scoped read would miss                                                                       |
| 1i   | A no-show's two goal counts are composed from the season's `rules.forfeit_ergebnis`, the absent side taking the loser's; `ergebnis` is then derived as `f"{team1.tore}:{team2.tore}"`, `None` if either is `None`                                                                                                                                             | A client could submit a result disagreeing with the goals rendered beside it, or a forfeit disagreeing with the regulation it is meant to express (I3a)                                                          |
| 1j   | `elfmeterschiessen` kept only on a fixture outside the Gruppenphase whose two goal counts are equal, discarded otherwise — a level group draw discards it too                                                                                                                                                                                                 | A shoot-out would stand against a fixture one side won on goals, or against a group draw that has no tie to break (I25)                                                                                          |
| 1k   | Each side's `name` and `shorthand`, the venue's `name` and `maps_link`, and the referee's `name` are composed from the rows the payload's ids name (I3) — which is why the normalisation runs after the refusals rather than before them                                                                                                                      | A save would store whatever names the client held; and composing first would leave the composer with no row for exactly the ids `REQ-ELIGIBILITY-002` and `REQ-BOOKING-001` turn away                            |
| 2    | Payload written wholesale with `$set`, and the return is not read. The keys come from `FLPatchSpielDataPayload`'s field set plus `ergebnis`; each object under one of those keys is the COMPOSED one, so step 1k's fields ride in under keys the payload itself names                                                                                         | A field absent from the payload is **overwritten**, not preserved; keys taken from the normalised fixture instead would put `saison_id` in the `$set`                                                            |
| 3    | A miss RAISES rather than returning, and the raise takes the transaction's earlier writes back with it (I2)                                                                                                                                                                                                                                                   | A missing match would be reported as a successful edit                                                                                                                                                           |
| 3a   | Every side a Spieltag clash releases is emptied, **before** step 5, and named in `released_sides` (I29, I30)                                                                                                                                                                                                                                                  | A slot the release opens would stay empty until the next save, and the preview would name a different set of fixtures than the save moved                                                                        |
| 4    | Where a slot's `Quelle` names a group placing, the standing is derived — the team rows through `build_team_pipeline`, inside the session on the save and outside it on the preview, the figures beside them from the group-phase fixtures this step already holds — and only for the groups referenced; a season whose bracket references none skips the read | A group the edit just completed would still read as unfinished, and seed nothing; figures re-read from `spiele` would rank the preview's bracket on the stored season rather than on the one it was handed (I29) |
| 5    | The season's bracket is resolved and every disagreeing fixture written (I23, I24a, I25), each reported with what that write destroyed (I29)                                                                                                                                                                                                                   | A winner would never reach the fixture whose `Quelle` names its match, and a deleted scoreline would read as an ordinary pairing change                                                                          |

**`dry_run=true` runs step 0, the whole of `judge`, a read-only step 3a, step 4, and a read-only step 5, and writes nothing** (I29).
It resolves the bracket over a season assembled in memory — the patched fixture and any released sides
substituted in, and the standings step 4 derives taken from that same assembly — and returns the same
`FLPatchSpielDataResponse` the save does. No transaction: nothing is written, and a preview that took a
write lock would be paying for a question.

**Step 0 reads the `saison_id` and nothing else, and the fixture itself comes off step 1's season**
(`fl_backend/app/api/spiele/admin_router.py :: patch_spiel_data`, then
`fl_backend/app/api/spiele/services.py :: stored_in_slice`) — so the normalisation and every refusal
stand on one slice rather than on two reads that could disagree (I45). Step 2's return is not read at
all: a miss raises, so the 404 is the helper's (I2) and the raise
unwinds the transaction rather than leaving the change half-applied. Step 5 must be scoped to one season, because `spiel_nr` identifies a match _within_ a
season, and `saison_id` is on no payload — so the `$set` cannot have moved the fixture out from under
the scope.

**More than one document, and still one transaction**, because the result and the advancement it causes
are one fact. Step 5's read takes the session, or it would see the snapshot from before step 2 and
resolve the bracket from the match as it was; step 4's takes it so the junction rows the standings
rank — each club's group and its `austritt` — are read at the same instant.

**A shoot-out rides with the result and is read only by the bracket** — step 5 takes a winner from it,
and the derived table does not (I25, I25a).

**No team document is written.** The league table is computed from the match documents by `GET /teams`
(I1), so entering a result moves the table on the next read. The frontend still invalidates the `teams`
cache tags in the same action — the data it caches changed even though no team document did.

### 1.4 Error codes and failure responses

**Every failure response body is `{error_code, correlation_id}`** — the full code table, the field
contract and the correlation-id design are in [`docs/logging/spec.md`](../logging/spec.md), which every
failure line and response must follow.
The invariant the tests pin here: the code on the wire and in the log is the **exception's own**
(`fl_backend/app/core/exceptions.py :: BaseAPIException`), checked by
`fl_backend/tests/api/test_error_responses.py`.

**A `DuplicateKeyError` maps to a 409 through a dedicated handler**: a natural-key
collision on a create is an ordinary outcome rather than a server fault. Starlette resolves handlers by
walking `type(exc).__mro__`, so registration order does not matter — the most specific registered class
wins.

**The match write path raises its own 409** (`REQ-WIRING-001`) for bracket wiring the season cannot
hold — §1.3 step 1b.
Same status, different meaning: no index refused anything, the season's current state did, and the
form prevents these shapes — so a request carrying one is stale or racing another admin.

**The rest of this path's rules carry codes of their own rather than `REQ-WIRING-001`'s**: that
code's advice is "reload the page", which is right for a season that has moved and wrong for every
one of these, where the season has not moved at all.

| Code                  | Refuses                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                         |
| --------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `REQ-ELIGIBILITY-001` | A team that has LEFT the season, standing on a fixture dated on or after its exit or on an undated one — judged on every save except one leaving every input the rule reads exactly as stored (`fl_backend/app/api/spiele/services.py :: find_eligibility_refusal`), so a payload CLEARING an exemption is judged exactly as one newly FIELDING the club; disqualified and withdrawn alike, the rule reading the date and never the `type`; a `nichtantreten_*` exempts the side it names in every phase, a no-show composing a result the table scores, while an `ausgefallen` or `annulliert` exempts both sides on a Gruppenphase fixture alone, a cancelled knockout advancing nobody; an abandoned fixture exempts neither |
| `REQ-ELIGIBILITY-002` | A newly fielded team with no `saison_teams` row for the fixture's season                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                        |
| `REQ-SPIELTAG-001`    | A team that would play two fixtures of one Spieltag, where the clash cannot be moved                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                            |
| `REQ-RESULT-001`      | A side carrying goals on a played fixture, emptied rather than switched                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                         |
| `REQ-STATE-002`       | Goals submitted against a `sonderereignis` that awards none — `ausgefallen` and `annulliert`                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                    |
| `REQ-STATE-003`       | A no-show recorded on a fixture one of whose sides is still unresolved                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                          |
| `REQ-DATE-001`        | A date outside the span of the matchday the fixture belongs to                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                  |
| `REQ-BOOKING-001`     | A venue or a referee NEWLY assigned to the fixture that the league holds no row for, or holds as retired — a reference already stored is left alone, so a venue may retire while only played fixtures name it                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                   |
| `REQ-CLASH-001`       | A venue or referee already serving another fixture less than four hours away                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                    |

**One code per rule, never one per side.** The failure body is `{error_code, correlation_id}` and
nothing else (L4), so the code is the only channel — and "team1 has left the season" and "team2 has
left the season" are one failure mode, which is what the code table's own rule keys on. The form works out
which side from the payload it submitted, using the predicates its pickers already evaluate.

**A malformed id: 404 in a path, 422 in a query — a deliberate split.** The `objectid` convertor
(`fl_backend/app/core/routing.py :: by_id`) means `/spiele/not-an-id` matches no route at all, and a
season id — a four-character string, never an ObjectId — reaches the lookup and 404s there instead. A
query parameter carries input, so malformed input fails validation like any other: `REQ-VAL-001`, 422.
`REQ-OID-001` (400) is the net behind both — bson's `InvalidId` mapped wherever a handler builds an
ObjectId no convertor or model has checked — and through routed traffic it is expected to be
unreachable.

### 1.6 The test suite

**The backend is the source of truth and the frontend mirrors it**, so the validation rules live here
and this suite pins them. Without it a constraint could be relaxed — to make a stubborn 422 go away,
say — and nothing would notice, because a loosened rule fails no test and breaks no build.
`fl_backend/tests/README.md` navigates the tree; the contract is here.

**Covers:** Pydantic model validation chiefly — every constrained model accepts a valid payload, rejects
the specific bad value each constraint exists to stop, and still accepts the legitimate edge cases that
look like bad values (an empty `stadtteil`, a null `ergebnis` for an unplayed match, an integral float
`mietpreis`). Plus the declared domain model, the database's own `$jsonSchema` validators and unique
indexes, the shared crud helpers with the query and sort builders behind a list read
(`fl_backend/tests/core/test_crud.py`), the filter builders, the response envelope, every router's
admin guard (`fl_backend/tests/api/test_admin_guard.py`), the order the routes are declared in
(`fl_backend/tests/api/test_route_order.py`), the refusal paths, and both aggregation pipelines —
what a pipeline _says_ and what MongoDB _computes_ from what it says. Plus, against a real `mongod`,
the write paths themselves: the match save, the season rollover and the reference fan-outs, each with
the mid-flight failure that has to take the whole write back — and for a rename, which embedded copies
it rewrites and which it must leave alone. What is reached only indirectly is §4.

#### The two tiers, and the marker that separates them

| Tier        | Selected by         | Needs Docker | Cost                                                |
| ----------- | ------------------- | ------------ | --------------------------------------------------- |
| **Default** | everything unmarked | no           | 8.4s warm (2026-08-20)                              |
| **`db`**    | `@pytest.mark.db`   | yes          | 60s warm (2026-08-20); cold adds the `mongo:8` pull |

**Both figures are warm developer-machine runs of the tier on its own**, each measured twice with the
`mongo:8` image already pulled. They say what a run costs here rather than what it costs in CI, and a
figure moves with the machine as much as with the suite.

`fl_backend/pyproject.toml :: addopts` deselects the marker, so a bare `pytest` runs the fast tier only.
A command-line `-m` overrides it — addopts are prepended rather than merged — so `pytest -m db` runs
exactly what the default run skips. Why each of the other flags is there is commented at that same key.

**A test that touches the database carries `@pytest.mark.db`.** Without it the test runs in the fast
tier, where there is no container, and fails for a reason that looks unrelated to what it is testing.
`--strict-markers` catches a misspelled marker; nothing catches an omitted one.

**The marker exists to keep the fast tier fast**, and a real `mongod` sits behind it because
`mongomock` cannot execute this pipeline and a check against the live database tests the data rather
than the code. The gate's `--backend` scope runs the default tier only; the `db` tier is its own
scope and its own parallel CI job ([`docs/ops/spec.md`](../ops/spec.md)).

An `*_execution.py` module runs against a real `mongod` what its structural sibling asserts about the
dict, and neither replaces the other: the structural test fails when a rule is **deleted**, the
executing one when a rule is present but **wrong**. `fl_backend/tests/api/test_spiele_pipeline_execution.py`
and `fl_backend/tests/api/test_reference_fanout_execution.py` have no structural sibling — the spiele
pipeline is exercised against the engine alone, and a fan-out is an `update_many` no assertion about a
dict can describe.

#### What the suite reads, and what it does not

Every field the application under test needs is passed explicitly to
`fl_backend/tests/config.py :: build_test_config`, and init arguments outrank every other source in
pydantic-settings, so a checkout with no `.env` runs the whole suite — which is what CI is — and a
failure means the code rather than the machine. **A field that is not passed still falls back to
`.env`**, which the settings model declares (`fl_backend/app/core/config.py :: model_config`), which is
why a test about a default asserts on the model's field rather than on a constructed instance.

**The container fixture lives in the root `conftest.py`**, not in `api/`, because two suites want a
database. It is session-scoped, so one `mongod` serves both, and it yields the _container_ rather than
a client: the pipeline suite reads with pymongo and the constraint suite drives Motor, which needs the
connection URL.

**One test guards a rule nothing else can.**
`fl_backend/tests/core/test_constraints.py :: test_every_mirrored_model_matches_its_validator` compares
each Pydantic model's stored field names against the `$jsonSchema` its collection carries and fails
naming the field, which is what makes a hand-written third copy of the schema affordable (I17).

There are **no `__init__.py` files** — `pyproject.toml` sets `--import-mode=importlib`, which needs none
and cannot suffer same-basename collisions.

#### Conventions

- **Fixtures are factories, not constants.** Every fixture returns a callable producing a fresh valid
  payload; a test calls it with the one field it wants to break, so each case states exactly what makes
  it invalid and no two cases can leak state through a shared mutable dict
  (`fl_backend/tests/conftest.py :: _factory`). Payloads are keyed the way MongoDB serves them — `_id`,
  not `id` — because that is the validation alias the models declare.
- **Reject-cases are parametrised.** One `pytest.mark.parametrize` per rule, listing every value that
  must fail, so adding a case is one line.
- **Comments explain the _why_, not the assertion.** Where a constraint exists because of a specific
  defect, the test says so.
- **Assert _which_ field failed when more than one could**, using the `assert_rejects` fixture
  (`fl_backend/tests/conftest.py :: assert_rejects`): a bare `pytest.raises(ValidationError)` passes
  whatever went wrong, so a test meant to prove one constraint stays green while an unrelated typo in
  the payload satisfies it and the constraint it names goes unenforced. Use it wherever the payload is
  hand-built rather than produced by a factory.
- **The `db` corpus is documented once**, in `fl_backend/tests/api/conftest.py`: its header derives
  every expected figure by hand, the tests assert against them, and each seeded team exists to make
  exactly one invariant observable.
