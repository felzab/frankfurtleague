# Planning a programme

- Plan a programme in its own session. The plan lays a path through the whole programme, one pull
  request per session; size each session to be worth its own branch without exhausting its context,
  and give a phase whose verification verdict must stand alone a session of its own.
- Have the plan audited cold and its findings fixed before the owner sees it, its critical path
  included.
- Where the plan's handoff protocol differs from this skill's, this skill wins.
- Write session one's starter, `START-<session>.md`, in [handoff-template.md](handoff-template.md)'s
  form, and have it audited with the plan.
- Keep the plan, the starters and the handoffs in the durable plan directory, with one copy of each
  document they cite. The programme's register holds every ruling, cited by row and never copied.
